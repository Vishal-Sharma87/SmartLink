WHY I BUILT IT

A short link became a backend exploration.

SmartLink started as a URL-shortening project, but evolved into an exploration of backend engineering concepts such as security, asynchronous processing, caching, link safety, analytics, and system reliability.

“
The goal was not just to make a URL shortener work, but to use a familiar problem to explore the engineering decisions behind a system that needs to remain secure, observable, and maintainable.
ENGINEERING BEHIND SMARTLINK

The project, in capabilities.

Each part reflects something implemented in the existing application.

↗

URL shortening

Compact Base62 short codes are generated and resolved through the application’s redirect flow.

!

Link safety

Destinations move through the existing verdict system: SAFE, SUSPICIOUS, PENDING_REVERIFICATION, UNVERIFIED, or MALICIOUS.

◌

Analytics

Click activity is modeled with browser, device, operating system, country, continent, time zone, and click time.

✓

Authentication

JWT-based authentication protects user operations, with a server-side signup session bridging email OTP verification.

◆

Asynchronous workflows

Kafka is used for queued link creation and click-analysis processing so those workflows can run independently.

▣

Backend architecture

Spring Boot controllers, services, repositories, MongoDB, Redis, Thymeleaf, and external safety/geolocation integrations work together.

WHAT I LEARNED

The details shape the system.

  • Designing APIs and data models before building the UI.
  • Keeping routing, authentication, and authorization explicit.
  • Separating responsibilities between controllers, services, and repositories.
  • Designing for asynchronous workflows and failure cases.
  • Turning raw analytics events into useful summaries.
